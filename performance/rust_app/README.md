# Performance-тесты локальной iOverlay

Стенд 0.2.0 подключает локальную iOverlay 9.0.1 через `../../iOverlay`. Прежний подход сохранён: один сценарий — один `src/test/test_N_name.rs`, запуск по номеру через **`--test N`**. Номера 0..8 и исходная геометрия этих тестов сохранены. Отдельного legacy-бинарника нет.

## Набор тестов

| Номер | Файл в src/test | Нагрузка / варианты |
|---:|---|---|
| 0 | test_0_checkerboard.rs | Исходная сетка перекрывающихся квадратов, Xor |
| 1 | test_1_not_overlap.rs | Исходная сетка разнесённых квадратов, Union; `--layout line` размещает квадраты вдоль X с O(1) активных рёбер |
| 2 | test_2_lines_net.rs | Исходные горизонтальные/вертикальные полосы, плотная сетка пересечений, Intersect |
| 3 | test_3_spiral.rs | Исходная float-спираль, Subject; `--spiral integer` — детерминированная ортогональная лента с центральным вырезом, Difference |
| 4 | test_4_windows.rs | Исходные окна/отверстия, Difference |
| 5 | test_5_nested_squares.rs | Исходные концентрические прямоугольные рамки, Xor |
| 6 | test_6_corrosion.rs | Исходные сетки многоугольников разных размеров, Difference |

| 8 | test_8_wind_mill.rs | Исходная сетка «мельниц», Intersect |
| **9** | **test_9_orientation.rs** | Длинные перекрывающиеся полосы; `--orientation horizontal/vertical/all`, точный поворот на 90°, Xor |

| **13** | **test_13_seeded.rs** | Детерминированные псевдослучайные прямоугольники, Xor |

Отдельные новые checkerboard, disjoint, grid, nested, windows убраны: соответствующие нагрузки уже представлены номерами 0,1,2,5/7,4. Целочисленная спираль и линейное размещение разнесённых фигур стали вариантами существующих номеров 3 и 1. Пара направлений находится в одном test_9; кластер и кластер с выбросом — в одном test_12.

В каждом `test_N_…` находится структура теста и генератор `geometry`. `test/mod.rs` связывает номера с этими генераторами. `test/runner.rs` содержит общий протокол проверки/измерения, `test/data.rs` — представление входа, PRNG, отпечаток и преобразование координат. `config.rs` разбирает параметры, `main.rs` запускает выбранные номера. Геометрия сценариев не спрятана в общем файле generators/fixtures.

## Запуск

Из каталога `/Users/nailsharipov/Projects/Rust/iShape/iOverlay/performance/rust_app`:

```bash
# Прежний способ выбора теста и размера; дополнительные опции необязательны.
./run.sh --test 0 --count 32 --complex false --multithreading false --int all

# Парное измерение направлений одной геометрии.
./run.sh --test 9 --count 128 --orientation all --strategy all

# Дополнительные нагрузки; один seed на весь выбранный набор.
./run.sh --test 10,11,12,13 --count 32 --seed 42

# Варианты существующих тестов.
./run.sh --test 1 --count 512 --layout line
./run.sh --test 3 --count 128 --spiral integer

# Полный базовый набор.
mkdir -p results
./run.sh --label my-machine > results/baseline.csv

# Только геометрия, независимая от sin/cos и float-адаптера.
./run.sh --test 0,1,2,3,4,5,8,9,10,11,12,13 --spiral integer > results/integer.csv

# Серия размеров в стиле старого complex-режима, с ограничением времени.
./run.sh --test 9,10,11,12,13 --complex true --budget-seconds 30

# Пороговые размеры: 3992,4000,8000,16000,16008 исходных рёбер.
./run.sh --test 1 --layout line --count 499,500,1000,2000,2001 \
  --mode cold --warmup 1 --samples 3 --iterations 1 > results/thresholds.csv

# Потоки требуют явного включения feature.
RAYON_NUM_THREADS=4 cargo run --release --locked --features multithreading -- \
  --test 1 --layout line --count 4096 --multithreading true --strategy auto,tree,frag

cargo test --release --locked --all-features
cargo clippy --release --locked --all-targets --all-features -- -D warnings
./run.sh --list
./run.sh --help
```

Без параметров запускаются 0..13, count=8, seed=0, int=i32, все четыре стратегии, оба режима, без потоков. test_9 и test_12 по умолчанию выполняют оба варианта. Поэтому полный default-прогон содержит **128 строк** CSV; с `--int all` — **384**. По умолчанию test_1 использует старую grid-геометрию, test_3 — старую float-спираль. `--layout all` и `--spiral all` включают оба варианта соответствующего номера.

`--test`, `--count`, `--strategy`, `--int`, `--mode` принимают списки через запятую или `all` там, где это указано в help. Для integer engine также поддерживаются старые обозначения 16/32/64. `--size` — алиас count, `--extended` — алиас complex=true. `--case` и legacy-feature удалены; пользуйтесь номерами.

complex=true, как прежде, выбирает серию размеров вместо count; теперь это ограниченная базовая серия 2,4,8,16,32,64. Квадратичные тесты 0,1(grid),2,4,6,8 ограничены count<=64, более дорогой 7 — count<=16; остальные — <=4096. В complex слишком большие комбинации пропускаются с сообщением stderr; при явном count сверх лимита возвращается ошибка. Масштабные старые complex-серии не запускаются автоматически.

## Измерение и проверка

Общий протокол применяется к старым и новым номерам: FillRule::NonZero, Precision::HIGH, стандартные integer output options. По умолчанию 2 warm-up операции и 7 выборок по 3 операции; параметры `--warmup`, `--samples`, `--iterations` изменяют это. samples допускает 3..101. Debug-замеры запрещены.

- **cold**: создание Overlay, загрузка готового входа, Boolean operation, освобождение результата и Overlay.
- **reuse**: восстановление исходных контуров через `reinit_with_subj_and_clip`, Boolean operation, освобождение результата; ёмкости Overlay сохраняются.

Генерация, преобразование координат, проверка корректности, canonicalization, отпечатки и вывод находятся вне таймера. Изменённые splitter-ом сегменты не переиспользуются как исходный вход. Используется black_box. Cold обозначает создание экземпляра, а не гарантированно холодный CPU/allocator cache.

Для исходных float-тестов 3/6/7 геометрия сохранена, а преобразование через тот же conservative FloatPointAdapter выполняется заранее с выбранным integer engine. Измеряется **integer-ядро Overlay**, без float-конвертации и float-очистки выходных контуров. Новые времена не сопоставимы напрямую со старыми опубликованными цифрами FloatOverlay. Float-входы используют sin/cos; межплатформенная побитовая стабильность не обещается, итоговая integer-геометрия может различаться между движками. Её реальный отпечаток фиксируется в CSV. Для строго стабильной спирали выбирайте `--spiral integer`.

Перед замером каждый результат сравнивается с List-эталоном и проверяется reinit. Сравниваются ориентированные выходные границы с независимостью от порядка фигур/контуров и циклической начальной вершины. Направления контуров сохраняются, отверстия учитываются. Это строгий компаратор границ для данного корпуса; расхождения не скрываются допуском. Для test_9 проверяется точное совпадение геометрии после поворота на 90°; превосходство horizontal не предполагается. Все пересечения этой пары целочисленные.

Мягкий `--budget-seconds` по умолчанию 30; значение **0 полностью отключает бюджет**; сборка не входит в бюджет. Проверки выполняются между комбинациями, warm-up операциями и выборками; одна операция/проверка корректности не прерывается. При исчерпании бюджета незавершённая строка и остальные комбинации пропускаются, stderr сообщает причину, завершённые строки сохраняются (exit 0). Проверяйте полноту CSV.

## Воспроизводимость и результаты

**CSV schema=2, fixture_version=2**: добавлены поля `test` и `variant`, изменён корпус. Прежний baseline schema=1 нельзя считать baseline новой матрицы; он сохранён локально в `results/previous-layout/`. Каталог results игнорируется Git. `Cargo.lock` фиксируется для этого executable.

CSV содержит параметры, фактическое число исходных рёбер input_edges, число контуров, bounding box, input fingerprint, число выходных контуров/рёбер, ориентированную удвоенную площадь и validated=true. Времена — целые наносекунды одной операции, усреднённые внутри выборки. Сохраняются медиана, min/max и все выборки по порядку. Для чётного количества выборок медиана округляется вниз. stdout — только CSV, сообщения — stderr.

Метаданные включают библиотечную версию/revision/dirty, source fingerprints библиотеки и runner (включая lock), время сборки, Rust/target/profile/opt-level/debug-info/RUSTFLAGS, ОС/доступные CPU, label машины, время запуска, feature потоков и RAYON_NUM_THREADS. Git-поля могут быть unknown вне Git. Для аппаратного сравнения задавайте label с моделью CPU и закрепляйте число потоков. После изменений библиотеки запускайте через Cargo, чтобы пересобрать бинарник.

SplitMix64 в data.rs использует собственный u64 state и wrapping-арифметику modulo 2^64:

```text
state += 0x9e3779b97f4a7c15
z = (state ^ (state >> 30)) * 0xbf58476d1ce4e5b9
z = (z ^ (z >> 27)) * 0x94d049bb133111eb
return z ^ (z >> 31)
```

Первые пять значений seed=0: `e220a8397b1dcdaf,6e789e6aa1b965f4,06c45d188009454f,f88bb8a8724c81ec,1b39896a51a8749b`.

test_13 генерирует 2n прямоугольников, попеременно Subject и Clip. Четыре значения на прямоугольник: x=r0%4096-2048, y=r1%4096-2048, w=8+r2%256, h=8+r3%256. Порядок вершин: (x,y),(x+w,y),(x+w,y+h),(x,y+h). test_12 использует два значения на пару: x=r0%512-256, y=r1%512-256; Subject 64×64, Clip того же размера со сдвигом (16,16); дополнительный квадрат 8×8 в (0,0) или (12000,12000). Modulo bias намеренно фиксирован.

Input fingerprint — FNV-1a 64, offset cbf29ce484222325, prime 100000001b3, wrapping-умножение. Для Subject, затем Clip хэшируются little-endian u64: число контуров, длина каждого и пары координат i64 в двоичном дополнении. Порядок входа значим; rule/version — отдельные поля. Это диагностический хэш; StdRng/DefaultHasher не используются.

Golden test_13 при count=8: seed=0 → 77ac91e43630115d, seed=42 → 95eba339e7c58a49, seed=u64::MAX → b3bbd963a77647f5. В cargo tests закреплены также отпечатки старых integer-генераторов, новых нагрузок и integer-спирали. При намеренном изменении входа обновляйте fixture_version и контрольные векторы.

## Ограничения

Каждая integer-координата проверяется до сужения типа: i16 [-16384,16383], i32 [-1073741824,1073741823], i64 [-4611686018427387904,4611686018427387903]. Не подходящие для двигателя комбинации пропускаются с сообщением stderr. Integer-fixtures не масштабируются под двигатель.

В текущей библиотеке Auto split: List при <4000 сегментов, Tree при 4000..=16000, Frag при >16000. Запрошенный Tree также переходит в Frag при >16000. Fill Auto имеет отдельный порог <8000 после splitting; Tree/Frag используют tree-fill. В CSV strategy — запрос, split_route_hint — оценка по исходным рёбрам; нормализация, слияние и повторные проходы могут изменить сегменты. Fill route также не инструментирован. Tree/Frag на больших данных нельзя выдавать за сравнение разных split-алгоритмов. Библиотека не изменена.

Малые smoke-данные обычно не достигают parallel-sort порога 32768; multithreading=true не доказывает фактическое распараллеливание. Test_10 содержит почти параллельные полосы с частичным перекрытием и без плотной сетки пересечений; плотные пересечения уже покрывает test_2. Строгие тесты используют размеры 1/4/8; большие или иные float-данные могут выявить новые расхождения — тогда runner сообщит ошибку.


## Короткий профиль для сравнения изменений

```bash
# Выполнять из performance/rust_app. Требуется Python 3.
python3 quick.py --output results/base.csv
# После изменения библиотеки — тот же фиксированный набор:
python3 quick.py --output results/experiment.csv --compare results/base.csv
```

`quick-v1` последовательно запускает номера 0..13 с заранее подобранными размерами.
Два движка i32/i64, четыре стратегии, cold/reuse, seed=42; 2 warm-up и 7 выборок
по одной операции. Итого **304 строки**. Потоки выключены. Сборка release выполняется
один раз перед набором; зависимости берутся offline из Cargo.lock.

| Тест | count | Варианты |
|---:|---|---|
| 0 | 24 | checkerboard |
| 1 | 499,500,2001 | line: 3992/4000/16008 исходных рёбер |
| 2 | 48 | lines_net |
| 3 | 256 | float и integer |
| 4 | 32 | windows |
| 5 | 192 | nested_squares |
| 6 | 10 | corrosion |
| 7 | 8 | concentric |
| 8 | 18 | wind_mill |
| 9 | 256 | horizontal и vertical |
| 10 | 160 | diagonal |
| 11 | 1024 | collinear |
| 12 | 128 | cluster и outlier |
| 13 | 512 | seeded |

Цель подбора: базовая версия на машине измерения выполняет **весь номер теста**
(оба движка, все стратегии, режимы, размеры и варианты, вместе с генерацией,
проверками и прогревом) быстрее 0,5 с. Это характеристика измеренного baseline,
**не тайм-аут и не гарантия на любой машине**. Размеры никогда не подстраиваются
автоматически. Изменение, которое замедлит тест, будет полностью измерено;
строки не отбрасываются. Профиль передаёт `--budget-seconds 0`.
Сборка и первый запуск свежего бинарника (включая возможную проверку ОС)
учитываются отдельно; перед набором выполняется `--help`.

Рядом с CSV сохраняется JSON: команды, фиксированный профиль, SHA-256 quick.py,
модель CPU, объём памяти, revision, время сборки/первого запуска, полное время
каждого номера, полнота результата и stderr. Существующие файлы не перезаписываются.
CSV сохраняет все исходные выборки и metadata Rust-стенда. При ошибке остаётся
JSON с complete=false; такой запуск не является baseline.

`--compare` требует одинаковые ключи, input fingerprint, выходные сводки,
runner_source, компилятор/target, параметры сборки и протокол измерений.
Меняться может исходник библиотеки. Различия в структуре контура или выходной
сводке требуют отдельной проверки; молча сравнивать их нельзя. Итоговый
`.comparison.csv` содержит baseline_ns/current_ns, change_percent и speedup.
Положительный change_percent означает замедление. Сравнивайте на одной машине
с одинаковой нагрузкой и энергорежимом; небольшие различия проверяйте повторным
запуском. Профиль не покрывает i16, многопоточность и весь диапазон больших данных.
